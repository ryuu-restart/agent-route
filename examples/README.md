# 可选配置参考

四套完整模板展示一种实现，不是安装器，也不是 Agent 接入的必经步骤。**实际目标与边界以 [AGENTS](../AGENTS.md)、[CLIENTS](../docs/CLIENTS.md) 和 [DNS-WEBRTC](../docs/DNS-WEBRTC.md) 为准。** Agent 可以按实际版本使用其他实现。

## 历史验证与能力要求

以下是截至 2026-11-02 整理的既有记录，不表示本次新增实机验证。验证版本不是整个项目的版本门槛；功能下限也不保证所有更高版本继续接受相同字段。

| 示例 | 历史记录 / 使用前需核实 |
| --- | --- |
| [Mihomo](full/mihomo.yaml) | 1.19.32：配置检查、隔离实例规则加载、DNS 与分流命中 |
| [sing-box](full/sing-box.json) | 1.14.4：配置检查、隔离实例 DNS 答案筛选与分流命中；模板使用 1.14.0 引入的 DNS 能力，其他版本须核对是否支持相应语义 |
| [Surge](full/surge.conf) | 历史仅做配置检查；模板的 `[Host]` 规则集引用要求 Mac 5.10.0+，这是功能下限，不是全版本验证声明 |

这些模板的历史检查不代表目标设备的 TUN、真实 DNS/WebRTC、IPv6、长期负载、重启或订阅持久化已通过。2026-11-06 补了 Mihomo 默认 TUN IPv6 地址的拒绝规则，并调整 sing-box 的节点引导解析器和内网名称解析；修订版通过了离线约束检查，固定核心的配置检查以对应提交的 CI 结果为准，没有重做隔离实例运行。2026-11-07 给 Mihomo 和 Surge 的 cn-ip 兜底加了 `no-resolve`，并写明 Shadowrocket 的共享备用解析器与混合答案限制；随后补充了合并时保留用户域名例外解析去向的说明（只改注释），同样没有重做实机或隔离实例运行。

## 参考方式

- 先识别实际核心与浏览器版本，查询对应官方文档、迁移说明、帮助或 Schema。版本升级可能弃用字段，不能把“最低版本以上”理解为永久兼容。
- 只合并必要部分，保留节点、订阅、用户例外与现有有效设置；不得把模板整份覆盖到用户配置。模板中的策略名称、解析器、引导和本地 DNS 前提都需现场核实。
- 必须保持规则语义、DNS 目标和可恢复性。不能为了沿用示例而升级/降级软件、放宽目标或丢弃用户例外。
- DNS 目标覆盖首次与连接建立时的再次解析；业务出站变为直连不等于 DNS 也应直连。`system/local` 只是可选实现，须核实核心实际使用的上游，不能凭系统界面或普通查询被接管就判内网解析通过。
- 模板只拒绝自己声明的 FakeIP 池和对应核心的默认 TUN 地址。现场设置了其他 TUN 地址时，按运行配置的实际前缀处理；sing-box 示例不含 TUN 入站，接口地址由现场配置决定，同样不能落进 LAN 直连。
- sing-box 示例的 `route.default_domain_resolver` 承担节点服务器域名的引导解析，指向不经代理的解析器；节点出站自带 `domain_resolver` 时以它为准，也不能经过该节点所在的代理。内网名称以域名形式进入时，示例先按 DNS 规则 `resolve` 再直连，避免被 DIRECT 的解析器送到公网。
- 合并时保留用户例外的解析去向。Mihomo 示例清空 `direct-nameserver` 后，订阅自带的域名直连规则改由 `nameserver` 经代理解析；Surge 示例里 `[Host]` 之外的名称走经代理的 `encrypted-dns-server`；sing-box 示例的 `dns.rules` 只覆盖项目名单，TUN / FakeIP 路径上的用户域名例外按未知域名解析。按同一域名条件为这些例外补 DNS 策略，表达不了时说明限制并由使用者选择。Shadowrocket 的 `direct-dns-server` 本身按 DIRECT 域名规则生效。不要为此恢复按业务出站选择的直连解析器：IP 规则命中的未知域名会随之改走直连 DNS。
- 中国 IP 兜底要看整组答案。Mihomo 和 Surge 的 IP 规则只测一个解析地址，模板因此给 cn-ip 加了 `no-resolve`：不在名单中的域名走默认代理，带真实地址到达的连接仍按 cn-ip 直连。代价是名单外的国内域名也经代理；去掉 `no-resolve` 能恢复域名兜底，但混合答案可能直连，须按[受限接入](../docs/CLIENTS.md#limited-integration)说明并由使用者选择。sing-box 示例在 DNS 阶段用 non-cn-ip 判断整组答案。Shadowrocket 测哪个地址、RULE-SET 能否带 `no-resolve` 都没查到资料，模板保持原样，须在目标设备核实。
- Shadowrocket 只有一项全局备用解析器，直连域名解析失败时也用它。模板让它经代理，避免海外和未知域名回退到直连；国内类的回退因此也经代理，不满足国内 DNS 全阶段直连目标，接入时按受限接入报告。不要清空它：社区手册说清空等于系统 DNS。
- 使用实际版本的检查方式核验候选，再在授权目标中逐项验证。没有充分证据就说明限制，不将 CI 结果当作设备验收。
